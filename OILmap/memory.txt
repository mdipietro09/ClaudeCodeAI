# OIL MAP — project spec (state as of 2026-09-23, MVP)

This file describes EXACTLY what the project is right now, so another
agent can maintain or rebuild it. OIL.html is the source of truth for
code and geometry; crude.xlsx / refined.xlsx are the source of truth for
the figures and their sourcing. Read all three before changing anything.

------------------------------------------------------------------------
## 1. Files
- OIL.html      — the whole app: one self-contained HTML file (~1160 lines).
                  Open directly in a browser, no build step. Needs internet
                  (loads D3 v7.8.5 + TopoJSON 3.0.2 from cdnjs, and the world
                  topology world-atlas@2/countries-110m.json from jsdelivr).
- crude.xlsx    — crude data. Sheets: Groups, Export flows, Chokepoints,
                  Notes & simplifications, Export-Import % (map data).
- refined.xlsx  — refined-products data. Sheets: Groups, Export flows,
                  Export-Import % (map data), Chokepoints, Notes & method.
- memory.txt    — this file.
There is no generator: the HTML data objects are kept in sync with the
xlsx sheets BY HAND.

------------------------------------------------------------------------
## 2. Page layout (shared HTML/CSS)
- Black page (--bg #000000, --fg #f0efec, --sub #a3a29c, --panel #161615,
  --panel-border #3a3a37), system font, 24px padding. Always dark; no
  light theme.
- Header "OIL MAP" (h1). Below it a segmented toggle: CRUDE | REFINED
  (.type-toggle / .type-btn; active button = light pill with black text).
- Two views, only one visible at a time:
    #crudeView   → map #crudeMap   + legend #crudeLegend
    #refinedView → map #refinedMap + legend #refinedLegend
  Each view = flex row: map column (fills space) + legend column (260px).
- One shared floating #tooltip div (dark panel, colored dot + title + body).
- Footer: "Data as of ~Sept 2026, see crude.xlsx and refined.xlsx for full
  sourcing, percentages, and routing notes behind every figure shown here."

------------------------------------------------------------------------
## 3. Code architecture — CRUDE and REFINED are independent (user rule)
Three <script> blocks:
 1. Toggle — the ONLY shared JS. Shows one view, hides the other, hides
    the tooltip.
 2. CRUDE  — wrapped in its own IIFE: own data, own svg, own legend, own
    helpers, own state.
 3. REFINED — its own IIFE with its OWN COPIES of every helper (duplicated
    on purpose; never share code between the two views).
- Every selector is scoped to the view's own svg / legend (svg.selectAll,
  legend.selectAll), never global d3.selectAll.
- SVG <defs> ids are document-global, so they're unique per view:
  crude: arrow, canadaStripes, kazakhstanStripes, latamStripes,
  azerbaijanStripes;
  refined: refined-arrow.
- Shared CSS only (classes .country, .route, .glow, .chokepoint,
  .label-text, .legend-*, .line-key*, .faded, .hovered, .selected, .dimmed).

Each view's script has the same structure:
  groups[] → groupByKey · countryInfo{} · euHub · euMemberCountries (Set)
  · chokepoints[] · originLabels[] / destLabels[] · routes[] · destGlow[]
  · render (projection, defs, tooltip helpers, focus logic, legend,
    then d3.json(topology) → countries, glows, routes, chokepoints, hub
    markers, labels).

------------------------------------------------------------------------
## 4. Rendering constants (both views identical)
- Projection: d3.geoNaturalEarth1().scale(200).translate([420,270]),
  svg viewBox 0 0 960 500. (Zoomed/shifted left so the empty Pacific is
  cropped and the Middle East/Asia are larger; Hawaii and the far Arctic
  fall outside. The Panama→Asia routes exit the left edge at [-178,32]
  and re-enter at [178,32].)
- Land: untracked countries landFill #262623 / stroke #4a4944.
  Importer countries importFill #43423e / stroke #5e5d57 (slightly lighter
  gray). Colored countries use their group color + group stroke.
- Routes: quadratic curves through ordered waypoints (curvePath with a
  per-route `bend`), stroke = group color, width 1.7, opacity 0.95,
  arrowhead at the end; dash:true → dasharray "4 3".
- destGlow: translucent circles at destinations, one per incoming group
  color (crude r=20, refined r=16, opacity 0.22).
- Chokepoints: small gray diamonds (#888780), hover tooltip, labeled.
- Hub markers: EU = hollow circle r6 stroke #e0ded4 at [15,48];
  refined also Singapore = teal-filled circle r5 at [103.8,1.35]
  (Singapore isn't a polygon at 110m resolution).
- Labels: white 11px text at [lon,lat] + dx (default 8) / dy. Every
  country with data has a visible name (user rule), EXCEPT North Korea
  on crude (label removed on purpose: too small). The United Kingdom is
  always written "UK" (labels and hover titles).

------------------------------------------------------------------------
## 5. Interactions (both views)
- Zoom & pan (added 2026-09-23): d3.zoom on each view's svg, scale 1–8×,
  wheel/pinch + drag, +/−/⟲ buttons (.zoom-controls, top-left of the map).
  Double-click zoom is disabled (double-click = select/deselect). All map
  content is drawn inside one <g class="zoom-layer"> — anything new must be
  appended to zoomLayer, not svg, or it won't move with the map.
  Constant on-screen size while zoomed: CSS var --k (set on the svg) divides
  .country/.route stroke widths and .route.dashed dasharray (arrowheads follow
  stroke width); the zoom handler rescales glows (r/k), chokepoint diamonds,
  [data-r]/[data-sw] hub markers, label font-size and dx/dy offsets, and
  (crude) the hatch patterns' patternTransform.
- Hover country → tooltip: name, group name (or "Importer (not part of a
  colored group)"), note, then "Export (100%)" list and "Import (100%)"
  list. Hover route → label + detail. Hover chokepoint/hub → its info.
- EU-27 members all hover/click as ONE entity "EU" (euHub data).
  Refined excludes Netherlands and Belgium (they're the ARA hub there).
- Three mutually exclusive focus modes (state vars in each IIFE):
  * activeGroup — click a legend oil type: its countries + its routes
    stay, everything else fades; other legend rows dim.
  * activeCountry — click a country (or EU hub / Singapore marker): its
    arrows in and out stay bright, all other arrows fade; countries at
    the other ends stay full; everything else fades; the clicked entity
    gets a white outline (.country.selected).
  * activeRoute — click an arrow: only that arrow bright, the countries
    in its from/to full + white outline, everything else faded, glow only
    at its end.
  Clicking the same thing again, the sea, or an untracked country resets.
  Selecting one mode clears the other two.
- Every route carries `from` / `to` arrays of entity names (topology
  names, 'EU', 'Singapore'; empty when the end is a region like "East
  Africa"). Country/arrow isolation depends on them — every new route
  MUST have from/to.
- Crude `minor:true` routes are hidden (display:none) on the overview and
  only shown when one of their countries, their oil type, or the arrow
  itself is selected.
- Legend hint text: "Click a type or a country to isolate it on the map".

## 8. Data conventions
- Each country: exports[] and imports[] each sum to exactly 100%, or a
  single {None, 0} row. Names in countryInfo keys must match the
  topology's properties.name exactly ("United States of America",
  "United Kingdom", "South Korea", "North Korea", "United Arab Emirates").
- Hard-sourced figures: crude EU hub (Eurostat Q1 2026), Canada's import
  split (CER), Iran 91% to China (Statista/UANI). Everything else is this
  project's estimate — the xlsx "Basis / notes" column says which.
- The 2026 scenario (Iran war, Venezuela blockade, Jan 2026 Maduro
  capture) is speculative/illustrative, not verified news. Directions of
  flows are real patterns; exact percentages are estimates.
- openpyxl gotcha: insert_rows does NOT move merged cells (the "EU-27
  member states" note row in crude "Export-Import %" is merged B:E).
  Unmerge before inserting, re-merge after.

------------------------------------------------------------------------
## 9. Checklist when changing data
1. Update the xlsx sheet (Export-Import %, Export flows, Groups…).
2. Update the view's countryInfo / routes / labels in OIL.html.
3. Every new route needs from/to (and, on crude, minor:true unless it
   meets the visibility rule). Every data flow between two mapped
   entities needs an arrow.
4. Every country with data needs a visible label (except North Korea).
5. Check sums = 100, re-render headlessly (Chrome --headless --screenshot)
   and look for label overlaps and JS errors.
6. Keep CRUDE and REFINED code separate.

## 10. Known gaps / possible next steps
- Refined: ~34 flows in the data have no arrow yet (crude is complete).
- Arrows are thin (1.7px) — a wider invisible click area would help.
- Latin America beyond Venezuela/Brazil/Mexico/Cuba is not tracked
  (Colombia, Ecuador, Argentina, Guyana, Chile/Peru).
- EU is one hub point, not per-country destinations.
- Figures should be re-verified periodically.
