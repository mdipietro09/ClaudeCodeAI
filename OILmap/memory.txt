# OIL MAP — project spec (state as of 2026-09-28)

Read this first. It describes the project exactly as it is, so another
agent can maintain it or rebuild it from scratch. Sources of truth:
  - OIL.html   → all code, geometry (coordinates, waypoints, label offsets)
                 and the data the page actually renders;
  - crude.xlsx / refined.xlsx / fields.xlsx → the same figures with their
                 sourcing and notes.
There is NO generator: the data objects in OIL.html and the xlsx sheets
are kept in sync BY HAND. Change both, always.

========================================================================
## 1. What it is
An interactive, dark, single-page world map about oil, with 3 tabs:
  CRUDE   — where crude oil goes: exporters colored by crude family,
            arrows for trade flows, 8 strategic chokepoints.
  REFINED — where refined products (diesel, gasoline, jet) go: exporters
            colored by refining/export role, arrows, same 8 chokepoints.
  FIELDS  — who controls the world's big oil fields: one colored circle
            per field, one color per company, focus on the Seven Sisters.
The 2026 scenario used throughout (Iran war, US naval blockade of
Venezuela, Maduro captured Jan 2026) is the user's illustrative scenario,
NOT verified news. Flow directions are real patterns; most percentages,
outputs and stakes are this project's estimates (the xlsx says which are
hard-sourced).

## 2. Files
- OIL.html     — the whole app, one self-contained file (~1860 lines). Open
                 in a browser, no build. Needs internet: D3 v7.8.5 and
                 TopoJSON 3.0.2 from cdnjs; world topology
                 https://cdn.jsdelivr.net/npm/world-atlas@2/countries-110m.json
- crude.xlsx   — Groups · Export flows (74 rows) · Chokepoints (8) ·
                 Notes & simplifications · Export-Import % (map data).
- refined.xlsx — Groups · Export flows (40 rows) · Export-Import % (map
                 data) · Chokepoints (8) · Notes & method.
- fields.xlsx  — Fields (97 rows) · Companies (28, sorted by oil
                 controlled, with color) · Seven Sisters (lineage + home
                 country) · Notes & method.
- memory.txt   — this file.

## 4. Code architecture — THE VIEWS ARE INDEPENDENT (user rule)
Four <script> blocks, in this order:
 1. Toggle — the ONLY shared JS: shows one view, hides the others, hides
    the tooltip.
 2. CRUDE  IIFE  (…"end CRUDE")
 3. REFINED IIFE (…"end REFINED")
 4. FIELDS IIFE
Each IIFE has its OWN data, svg, legend, state and its OWN COPY of every
helper (tooltip, curvePath, diamond, zoom…). Duplication is deliberate:
never share code between views. Selectors are scoped to the view's own
svg / legend (svg.selectAll, legend.selectAll) — never global.
SVG <defs> ids are document-global, so they are unique per view:
  crude: arrow, canadaStripes, kazakhstanStripes, latamStripes,
         azerbaijanStripes · refined: refined-arrow · fields: none.
Shared CSS classes only: .country .route .glow .chokepoint
.chokepoint-halo .field .label-text .legend-* .line-key* .zoom-controls
.faded .hovered .selected .dimmed, plus .fields-legend/.company-list/.tag.

Common to all three maps:
- Projection d3.geoNaturalEarth1().scale(200).translate([420,270]),
  viewBox 0 0 960 500 (shifted left: empty Pacific cropped; Hawaii and far
  Arctic fall outside; Pacific routes exit at [-178,32], re-enter [178,32]).
- Land: landFill #262623, stroke #4a4944.
- Zoom & pan: d3.zoom on the view's svg (crude/refined 1–8×, fields 1–12×),
  wheel/pinch + drag, +/−/⟲ buttons top-left. Double-click zoom disabled
  (double-click = select/deselect). EVERYTHING is drawn inside one
  <g class="zoom-layer"> — append new things there, not to svg.
  On-screen size stays constant: CSS var --k (set on the svg) divides
  stroke widths/dasharrays; the zoom handler divides radii (glows, hub
  circles via data-r, field circles), [data-sw] stroke widths, chokepoint
  diamond size, label font-size and dx/dy, and (crude) hatch
  patternTransform.
- Click the sea (empty svg) = reset every focus.
- Country names in data must match the topology's properties.name
  exactly ("United States of America", "United Kingdom", "South Korea",
  "North Korea", "United Arab Emirates", "Côte d'Ivoire", "Congo").
  "UK" is always written "UK" in labels and titles.

## 5. CRUDE and REFINED — shared design (each view has its own copy)
Data per view: groups[] (+groupByKey) · countryInfo{} · euHub ·
euMemberCountries (Set) · chokepoints[] · originLabels[]/destLabels[] ·
routes[] · destGlow[] (refined also singaporeHub).
- countryInfo[topologyName] = {group (key or null = importer), note,
  exports:[{to,pct}], imports:[{from,pct}]}. Each list sums to exactly
  100, or is a single {None/0} row.
- Colored countries = group color + group stroke. Importers (group null)
  and EU members: importFill #43423e / stroke #5e5d57.
- EU-27 members hover/click as ONE entity "EU" (euHub: point [15,48],
  hollow circle r6 stroke #e0ded4; its own imports list). Refined
  excludes Netherlands and Belgium (they are the ARA hub there).
- Routes: {pts:[[lon,lat],…] waypoints exporter→importer, group, dash,
  bend, from:[entities], to:[entities], via?:[chokepoint names],
  minor? (crude only), label, detail}. Drawn as quadratic curves
  (curvePath with per-segment `bend`), width 1.7, opacity 0.95,
  arrowhead at the end; dash:true → "4 3". from/to hold topology names,
  'EU' or 'Singapore' (empty for regions like "East Africa"); every
  route MUST have them — isolation depends on them.
- destGlow: translucent circles at destinations, one per incoming group
  color (crude r20, refined r16, opacity 0.22).
- Labels: white 11px at [lon,lat] + dx (default 8) / dy. Every country
  with data has a visible label (user rule), except North Korea on crude.
- Hover: country → name, group (or "Importer…"), note, "Export (100%)"
  and "Import (100%)" lists · route → label + detail · hub → its info.
- FOUR mutually exclusive focus modes (state vars in each IIFE; picking
  one clears the others; clicking the same thing again or the sea resets):
  * activeGroup   — legend oil type/exporter row: its countries + routes
    stay, the rest fades, other legend rows dim.
  * activeCountry — click a country / EU hub / Singapore: its arrows in
    and out bright, countries at the other ends full, the rest faded,
    clicked entity outlined white.
  * activeRoute   — click an arrow: only it bright, its from/to countries
    full + white outline, glow only at its end.
  * activeChoke   — click a chokepoint: every route through it bright
    (crude: minor ones shown too), their end countries full + outlined,
    other chokepoints fade, clicked diamond outlined white.
- STRATEGIC CHOKEPOINTS (8, both views; user rule): Strait of Hormuz
  [56.25,26.6], Bab-el-Mandeb [43.4,12.6], Suez Canal [32.3,30.5], Strait
  of Malacca [100.5,3.5], Panama Canal [-79.5,9], Cape of Good Hope
  (crude [18,-34], refined [18,-34.4]), Danish Straits [11,56], Turkish
  Straits [29,41.1]. Each: {name, control, c, dx?, dy?, detail}.
  Style (per-view consts chokeColor '#ffd84d', chokeSize 6.5): yellow
  diamond, black stroke, translucent yellow halo ring (.chokepoint-halo
  r11) and bold yellow label.
  HOVER (user rule): FIRST "Controlled by: …", then detail, then "Flows
  through it (n):" list, then "Click to isolate."
  Controlled by: Hormuz = Iran (north) + Oman (Musandam, lanes in Omani
  waters) · Bab-el-Mandeb = Yemen + Djibouti (Eritrea nearby; Houthi
  attacks since late 2023) · Suez = Egypt (Suez Canal Authority) ·
  Malacca = Malaysia, Indonesia, Singapore (joint patrols) · Panama =
  Panama (Canal Authority since 1999) · Cape = South Africa's coast, open
  ocean, nobody can close it · Danish Straits = Denmark (+ Sweden on the
  Øresund; 1857 Copenhagen Convention) · Turkish Straits = Turkey (1936
  Montreux Convention).
  routesThrough(cp) = routes with a waypoint on cp.c (tolerance: crude
  1.1°, refined 0.5°) OR naming it in via[]. A new route that crosses a
  chokepoint needs a waypoint on it or a via tag.
- Legend: title + hint ("Click a type, a country or a chokepoint to
  isolate it on the map. Scroll or pinch to zoom, drag to pan.") ·
  clickable group rows · "ROUTES:" solid/dotted key · "STRATEGIC
  CHOKEPOINTS (8):" key listing them.

### 8.2 Ownership / color rule (user rules)
owner = a Seven Sisters successor if one is involved AT ALL — operator,
subsidiary (Imperial Oil = 69.6% ExxonMobil; Azule = 50% BP) or partner
stake/contract — taking the operator first, else the biggest known stake
("if it's related to Exxon, color it Exxon"). Otherwise the operator /
controlling company. Consequences: Upper Zakum, Kashagan, Block 17,
Prudhoe Bay, Bacalhau, Athabasca, Permian → ExxonMobil; ADNOC Onshore
fields (Bu Hasa, Bab, Asab) and Kirkuk → BP; Tupi, Mero, Sapinhoá, Block
6, Val d'Agri (Eni-run, Shell 39%) → Shell; Orinoco, Lake Maracaibo,
Bakken, Vaca Muerta → Chevron. Eagle Ford has no Sister → EOG.
Sister detection sisterOf(name) = FIRST WORD in {ExxonMobil, Imperial,
Esso, Chevron, BP, Shell, Azule} ("Aker BP"/"BPRL" are not BP;
Sakhalin-1's seized Exxon share is written "Unallocated 30% (seized from
ExxonMobil…)" so it doesn't count). No stripes/hatching (user rule).

### 8.3 Rendering
- Circle per field: r = 2.2 + sqrt(kbd)·0.13 (÷k on zoom), fill = owner
  color, black 0.8 stroke; drawn biggest-first so small ones stay on top.
- Countries with a field #33322e, others landFill.
- MAP LABEL = the OWNER COMPANY's name (companies[k].label || name), NOT
  the field name (user rule). Greedy placement: biggest field first, a
  label is hidden if it overlaps one already placed; layoutLabels() re-
  runs on zoom, on every focus change, and via a MutationObserver when
  #fieldsView is un-hidden (labels can't be measured while hidden).

### 8.4 Interactions
- Hover a field — title "Field name (Country)" (user rule), then:
  "Belongs to: <company> <flag> — <nationality> company" (FIRST, user
  rule) · ownership line (private / state-owned…) · Seven Sisters lineage
  or Eni's challenger line · if the owner doesn't operate: "<owner> is a
  partner (stake or contract); the field is operated by <op>" (basins:
  "is one of the main producers in this basin") · Operator · Concession
  holders (equity %) [or "Companies involved" when any % unknown; Sister
  names in their color] · Concession / contract · "Discovered <year> ·
  ~<kbd> kb/d" · note · history (italic).
  "Operates" test = opSis === owner, or the operator text contains the
  owner's first name word or any aka.
- Click a field = white outline on it + isolate ALL fields of the same
  owner worldwide (activeKey). Click a company in the legend = the same
  (ONLY the fields it owns — not fields where it merely has a stake).
  Either way the other legend rows dim and the active row scrolls into
  view. Click again / the sea = reset.
- Hover a country = its fields with owners; click a country = isolate its
  fields (activeCountry).
- State: activeKey, activeField, activeCountry (mutually exclusive).

### 8.5 Legend (user rules)
- "COMPANIES — BY OIL CONTROLLED:" + hint ("Each color is one company.
  Click a company (or a field) to isolate the fields it controls. Hover a
  field for details and partners. …").
- ALL 28 companies in a scrollable .company-list, sorted by oil
  controlled (sum of kbd of owned fields). Row: color swatch, name, emoji
  flag + nationality, "Seven Sisters" / "challenger" tag, "~X kb/d in N
  fields · stakes in M more" (M from involved(): owner, Sisters via
  f.sisters, others via aka whole-word matches in operator/partners).
- Then "FIELD SIZE (crude + condensate output):" key (100 · 1,000 · 3,000
  thousand barrels/day) and "97 oil fields, 28 companies…" line.
- The legend is exactly as tall as the map, CSS only:
  .fields-legend { align-self:stretch; contain:size } (the map sets the
  row height; the list flexes and scrolls); under 760px wide it falls
  back to max-height:70vh. Don't use a ResizeObserver (it fired too late).
- Emoji flags show as 2-letter codes on Windows; nationality is always
  written out too.
