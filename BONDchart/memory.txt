WHAT THIS PROJECT IS
--------------------
Weekly candlestick chart of the Italian BTP bond IT000553414 (4.5% Oct-2053,
price typically 90-106 points), built with pandas + plotly. The user
downloads fresh daily OHLC price data into data.csv (Investing.com-style
format: MM/DD/YYYY, quoted numbers, utf-8-sig BOM, newest row first),
manually writes a macro/geopolitical briefing into macro.xlsx, then runs
ONE command to rebuild everything:

    python3 run.py
        AI maintenance (Ollama) -> PLOT.html -> FORECAST.html

    python3 run.py "some free-text instruction"
        Same, but the instruction is injected into every AI prompt and
        always forces a fresh forecast vintage (see FORECAST.XLSX below).

FILES (everything is just these 5 + outputs)
----------------------------------------------
- run.py            THE WHOLE PIPELINE. One file, no other .py modules in
                     the pipeline. Contains: S/R level clustering, the
                     Ollama-driven forecast maintenance (post-mortems +
                     re-anchoring), the main chart build, and the
                     forecast-review chart build. Sections are numbered
                     0-6 with banner comments — read top to bottom.
- data.csv           daily price data, user downloads/refreshes this.
- macro.xlsx         macro/geopolitical narrative — MAINTAINED BY HAND by
                     the user, every run. Columns: date, icon, text,
                     summary (see SCHEMAS below). The AI never writes
                     date/icon/text — only the `summary` column.
- forecast.xlsx      append-only log of every 4-week forecast vintage the
                     AI has ever made, plus HIT/MISS scoring notes. AI
                     writes this; user can hand-edit if wanted (e.g. to
                     fix icons).
- PLOT.html          OUTPUT — main chart.
- FORECAST.html      OUTPUT — forecast-vs-actual review chart.
- _api.py            untouched, unrelated, unused investiny data-fetch
                     snippet. Not part of the pipeline.

Deleted from the project (no longer exist, don't recreate unless asked):
sr_levels.py, ai_maintenance.py, forecast_plot.py, macro_events.xlsx,
update.py — all consolidated into run.py or superseded by macro.xlsx.

SCHEMAS
-------
macro.xlsx: date, icon, text, summary
  - date:    any weekday the user actually wrote the entry on (not
             required to be a Friday). run.py SNAPS it to that week's
             Friday to match it against the weekly candle — so date any
             day you want, it'll still land on the right week. Two rows
             landing on the same Friday: the most recently WRITTEN one
             (by `date`) wins, older one is dropped from the chart.
  - icon:    user-chosen emoji, floats above that week's candle.
  - text:    freeform long-form briefing (markdown-ish: **bold**, links,
             newlines). Never truncated/rewritten by the AI.
  - summary: AI-written IF EMPTY, one short sentence condensing the single
             most important event from `text`, paired with the icon on
             the chart hover (the raw `text` is too long for a hover/every
             AI prompt). User can hand-edit any cell — AI only fills
             EMPTY summary cells, never overwrites a non-empty one. Clear
             a cell to force the AI to rewrite it next run.

forecast.xlsx: week_end, Open, High, Low, Close, icon, text, made_on,
               anchor_close, note
  - APPEND-ONLY. A "vintage" = all rows sharing one made_on/anchor_close.
    NEVER delete rows — history is the point (track record + lessons).
  - icon/text: AI-written per forecast week, following ICON_CONVENTION in
    run.py (same convention used for macro.xlsx icons, defined once,
    reused everywhere to avoid disagreeing icon lists).
  - note: post-mortem on a MISSed completed week (why + lesson learned,
    fed back into future prompts), OR "superseded by <date> re-anchor
    (<reason>)" on an upcoming row a newer vintage replaced.
  - PLOT.html plots only the LATEST vintage's still-future rows.
  - FORECAST.html plots every vintage, but a row marked "superseded" is
    EXCLUDED from that vintage's line/band (only kept in the .xlsx for
    history) — so if two forecasts land on the same week, only the
    latest one is drawn; older vintages' lines just stop at their last
    still-live/completed week instead of overlapping.

RUN.PY PIPELINE (in order)
---------------------------
0) AI MAINTENANCE (Ollama, local model — change `llm` var at the top of
   run.py to switch models; currently 'gemma4'). Talks to
   localhost:11434 via stdlib urllib only, no pip deps. If Ollama isn't
   running, this step is SKIPPED with a warning and the chart still
   builds from the existing xlsx files.
     a) maintain_macro_summary — fills any EMPTY macro.xlsx `summary` cell.
     b) market_context() — builds the shared prompt context: recent
        weekly candles, S/R levels, ATH/ATL, AND the latest macro.xlsx
        summary as "ground truth for current events" (the AI has ZERO
        other awareness of the real world — it only knows what's in this
        context, never assume it knows current events on its own).
     c) maintain_forecast — writes a post-mortem `note` on any completed
        MISS lacking one; re-anchors (new 4-week vintage) if price
        drifted > REANCHOR_TOLERANCE (0.30 pts) from the live vintage's
        anchor, a completed week of the live vintage MISSed, or the user
        passed free-text instructions (always forces re-anchor).
1) build_main_chart — weekly candles + daily-view toggle (W/D pill,
   top-left), filtered S/R levels, ATH/ATL lines, macro.xlsx markers,
   4-week forecast candles (blue) + a deterministic daily expansion of
   them, FORECAST divider, white 100.00 line. -> PLOT.html
2) build_forecast_review_chart — every non-superseded forecast vintage
   as a Low-High band + Close line (color ladder: darker = older, bright
   blue #66b8f2 = live), ✅/❌ verdict markers with post-mortem notes on
   hover, same S/R/100-line overlay, same W/D toggle (flips actual
   candles only). -> FORECAST.html

KEY CONVENTIONS / GOTCHAS
--------------------------
- ICON_CONVENTION (run.py): defined ONCE, reused in SYSTEM_PROMPT and the
  re-anchor prompt, so the model never sees two disagreeing icon lists.
  clean_icon() strips to just the first token (the model sometimes
  returns "🇪🇺 ECB" instead of "🇪🇺" — would render as literal text on
  the chart otherwise).
- SYSTEM_PROMPT deliberately has NO hardcoded storyline or dates (a past
  "next ECB meeting is 10 Sept" baked in forever was a real bug that got
  fixed) — all current-events grounding comes from market_context()'s
  live macro.xlsx summary, refreshed every run. If forecasts start
  ignoring reality, check that macro.xlsx actually has a recent row.
- W/D toggle JS: TOGGLE_SNIPPET is filled via inject_toggle(), which MUST
  json.dumps() the boolean mask lists — Python's str() on a bool list
  produces invalid JS ([True, False] instead of [true, false]) and
  silently breaks the click handler. This broke once; don't regress it.
- Weekly is the driver: S/R, ATH/ATL, macro markers and forecast are all
  computed on the WEEKLY resample; daily is visualization-only (each
  weekly forecast candle is deterministically expanded to 5 daily
  candles reproducing the same OHLC exactly).
- Trace order matters for the W/D toggle's visible-mask indices in both
  build_main_chart (traces 0/1 history, 2 macro icons, 3/4 forecast, 5
  forecast icons — 2 and 5 stay visible in both views) and
  build_forecast_review_chart (0/1 actual candles only) — if you add a
  trace, update the mask indices passed to inject_toggle().
- sane_candle() clamps any AI-written forecast candle to anchor ± 6.0 pts
  and correct H/L/O/C ordering before it's ever written to forecast.xlsx.
- Same-day re-anchor: if a new vintage's made_on <= the live vintage's
  made_on, +1 hour is added so the two vintages don't merge into one.

THE ROUTINE (what to do each session)
---------------------------------------
1. User downloads fresh data.csv and hand-writes a new macro.xlsx row
   (any weekday, icon of their choice, long-form text — summary is
   optional, AI fills it if left empty).
2. `python3 run.py` — does everything: AI maintenance, PLOT.html,
   FORECAST.html. That's the only command needed.
3. If the user wants to force a fresh forecast regardless of drift, or
   steer it (e.g. "make the icons less repetitive"), pass free text:
   `python3 run.py "instruction here"`.
4. Never delete forecast.xlsx rows or macro.xlsx rows — this is a
   track-record/history project by design.
